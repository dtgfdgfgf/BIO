# 紀律零＋九條（通用版全文）

> **Summary (EN)**: The full text of the ten iteration rules, generalized from the project. Each rule has three parts: why it exists (the failure that triggered it, anonymized), the rule itself, and how it is enforced (script check or human sign-off). Rule zero is a stage gate that decides whether a round may touch thresholds at all. Rules one to seven govern how a change is diagnosed, typed, predicted, evidenced, audited, budgeted and costed. Rule eight governs the choice of method family. Rule nine requires the agent to look at every candidate image before handing a review pack to a human.

適用範圍：一切「改演算法相關行為」，包括程式、門檻與常數、判定條件、ROI 定義、特徵表示法、配方預設值、參數搜尋範圍。研究期和定版後都適用；讀完人工覆核結果、要動手修正的時候尤其適用。

## 名詞

| 名詞 | 意思 |
|---|---|
| 候選 | 演算法產生、可能是瑕疵的一塊區域，例如一個輪廓、一條路徑 |
| 認同／過殺／漏檢 | 人工覆核的判定。過殺＝演算法說有、人說沒有；漏檢＝人畫出來、演算法沒抓到 |
| 覆核包 | 一輪交給人覆核的候選集合，附圖和說明 |
| 凍結基準 | 上一版演算法對同一批影像的完整輸出，用來逐候選 diff |
| 翻轉 | 同一個候選在新舊版之間的判定改變 |
| 封存集 | 事前抽樣鎖住、改法期間不准看逐張結果的影像 |
| 方法族 | 候選產生階段用的方法大類，例如全域門檻、濾波、分割、學習式 |
| 量名 | 演算法內部的量，例如面積、寬度、某個比例 |

## 紀律零：開工前四問（階段閘門）

**為什麼**

工業 AOI 的收斂有順序：**定義 → 成像 → 結構 → 判別 → 邊界**。上游還沒收斂時調下游參數，做的功是負的：調出來的參數會變成沒人能解釋的歷史包袱，上游一改就全部重來。

觸發案例：一輪 224 萬 token 的多代理分析，在幾百條候選的數值裡找分隔面，提了三個修改案，整輪沒有打開任何一張圖。當時已有的七條紀律一列不缺，還是走錯了，因為那些紀律只管「怎麼改」，沒有一條問「該不該進入改門檻的階段」。最後看兩張放大圖就推翻了：兩類東西一眼可分，真正的問題是「這類東西算不算瑕疵」的定義題。詳見 [growth/04](../growth/04_two_images_vs_2m_tokens.md)。

**規則**

每輪開工前先回答，答案要指向檔案：

1. 這條線的瑕疵定義拍板了嗎？只有備註、沒有選選項，不算拍板。
2. 這個缺陷在目前的成像條件下穩定可見嗎？
3. 產品的每一層都建模了嗎？**哪些還沒有？**
4. 這一輪要關掉哪一個開放問題？
5. 這條線最簡單的基準方法跑過了嗎？它在哪些圖上失敗、原因是什麼、指向修同族還是換族？第五題只在第一個原型前和每次換方法族時必答，其他輪次填「不適用」並引用既有的方法選擇書。

- 任一題答「否」：本輪**不得產出跟門檻或判定有關的覆核包**，只能做那一題的上游工作，例如定義包、結構包、方法包、問題澄清。第五題答「否」，只能出方法包。
- **重型分析只在閘門通過後啟動**，包括多代理工作流、全量統計、對抗驗證。多代理放大的是執行品質，不是方向正確性：五個代理讀同一份紀律、跳過同一個階段，只會錯五倍。閘門之前只花對話成本。
- **開放問題有壽命。** 同一題掛滿 2 輪沒答，這條線就停止出新包，改出問題澄清包。結案只有兩種：之後某一輪重掛並答完，或使用者明說不答、已過時。開放問題越來越多，是比任何過殺率都更該警覺的訊號。
- **每一輪的目標是關掉一個開放問題，不是改善一個數字。** 開發集分數上升很便宜，同一個翻轉可以用五種故事解釋；不確定性下降才是進展。

**執行方式**：人簽核。LLM 填答案並附證據路徑，使用者點頭才開工。開放問題的掛輪數由總帳腳本自動算。

## 紀律一：先診斷，不改碼

**為什麼**

覆核迴圈的天然目標是「讓這些圖過」。讀完覆核結果就直接改碼，等於朝這個目標走最短路徑：加一個比例、推一下門檻、針對某一批特判。

**規則**

- 讀完人工覆核結果後，第一個產物是**診斷表**。這時不得動任何程式、配方或門檻。
- 診斷表欄位：候選 id｜影像｜**我看到什麼**｜人工判定與備註原文｜失敗的管線階段｜物理原因｜類別。
- **先看圖再填表。**「我看到什麼」用自然語言寫顏色、形態、連續性、和周圍結構的關係，**不得出現任何量名**。這一欄空白或含量名，整張表退回。
- **沒看圖不准講形態。** 沒看過圖的候選，只能引用數值，不能寫「細絲」「團塊」「稜線」這類形態詞；抄前一輪的描述不算看過。
- **看圖預算每輪 25,000 tokens 以內。** 一張放大裁圖約 870 tokens，一張整圖疊圖約 2,200。整包全看約 9 萬 tokens，只是一次重型數值分析的 4％。**看圖不貴，貴的是拿來替代看圖的分析。**
- **類別成立的條件**：同一類至少 2 例，而且能用同一句物理解釋說明。單例列進「無法一致解釋」清單，本輪不處理，回覆裡明列。
- **類別成立不等於可以提案。** 提案在凍結基準上只翻轉 1 條以下，等同單例，退回。同類 11 例、現行只有 1 例被放行時，任何針對這類的規則都只會翻轉那 1 例，跟單例過擬合在 diff 上分不出來。這時正確的結論是「現行表示法對這類沒有辨別力」，該走定義變更。
- **改動的影響範圍不得大於受益範圍。** 為了一張圖或一個候選，去動會影響大部分圖片的全域數值（全圖二值化門檻、背景模型參數、結構帶幾何），一律退回，即使那個候選是人已經認同的漏檢。提案要並列「受益幾張」和「影響幾張」；受益只有 1 張，直接列為已知限制，不提案。這條的起因是我說的一句話：「你又犯了一個錯，為了接回一張圖，想去嘗試動二值化這種影響大部份圖片的數值。」
- **候選溯源。** 討論一條候選該不該通過之前，先回答：它由哪些像素構成、在管線哪一階段產生、原本是什麼形狀。診斷表要分清**產生階段**的錯（這條候選根本不該存在，例如二維團塊被線化）和**判定階段**的錯（候選該存在但判錯）。**產生階段的錯，不得用判定階段的條件補救**，那是貼補丁。

**執行方式**

- 「我看到什麼」不含量名、翻轉集 1 條以下退回、看圖預算：機械檢查。
- 受益／影響張數：提案表固定欄位，缺欄不得進包。
- 候選溯源：人簽核。標為「產生階段」的，本輪只能走定義變更或表示法路線。

## 紀律二：每個改動先貼類型標籤

| 類型 | 定義 | 前置條件 |
|---|---|---|
| bug | 程式行為和文件描述不符 | 指出哪裡不符；修完後行為＝文件描述 |
| 定義變更 | 改物理定義：瑕疵是什麼、ROI 是什麼、用什麼表示法 | **先改定義文件再改碼**，回覆引用那一段 |
| 門檻重校 | 只動既有常數的數值 | 必附紀律四的分佈與靈敏度 |
| 新增條件 | 新的比例、分支、特徵、特判 | **預設禁止**。先寫出物理意義、對應診斷表哪一類、涵蓋幾例，使用者核准才能加 |
| 換方法族 | 候選產生階段的方法換到另一族 | **先寫換族聲明**（紀律八）；寫不出來就不得換；使用者在基準失敗圖上簽核 |

一次改動同時屬於好幾類時，每一類的前置條件都要滿足。

**定義變更的寫法**

- **寫「它跟正常的東西差在哪」，不寫「它長什麼樣」。**「細絲是細長的東西」無法否證；「A 是黃色斷續團塊，B 是粗細恆定的連續深色絲」可以直接變成量測。
- **異物類瑕疵用排除法定義**：異物＝不能被產品任何已知組成解釋的殘餘。列舉法（細長、有對比、不沿結構邊…）永遠補不完，排除法可以窮舉。每新增一個已知結構的建模，要同時說明它會吸收掉哪些現有候選。
- **未建模區不得當成異物證據。** 候選落在系統還沒建模的區域時，判定要保守，不得因為「不在任何已知結構內」就更像異物。
- **新特徵提案前先做安慰劑檢驗。** 把 N 條人工認同的候選逐一假裝成過殺，用同一個特徵池看各能被幾個特徵分出去。目標候選能被分出去的特徵數，如果沒有顯著高於隨便一條認同候選，這些特徵就不是類別證據。實例：166 個量裡有 41 個能分出某一條過殺，但純機率期望約 26 個，另一條認同候選甚至有 58 個。

**執行方式**：新增條件、換方法族＝人簽核；安慰劑檢驗＝機械。

## 紀律三：改之前先預測，改之後對 diff

**為什麼**

LLM 事後解釋結果的能力很強，數字變好之後總能補出一個故事。預測要寫在改動之前，裁定要交給 diff 檔。

**規則**

- 動手前寫**改動計畫**：預期翻轉哪些候選或影像（列出 id）、預期哪些不翻轉、封存集預期翻轉幾張。
- 改完後對**凍結基準**逐候選 diff，列出全部翻轉，分「預期」和「非預期」。
- **非預期翻轉大於 0＝退回**，先解釋，再決定要不要重提。
- 裁定依據是 diff 檔，不是 LLM 的自評。
- **保護反例。** 改動計畫要列「這個改動最可能誤殺的認同候選」，至少一條，而且必須出自人工指認過的範例集。改後保護反例翻轉＝退回；**沒有保護反例，不得宣稱修改安全。**
- **預期中間結果與否定條件。** 改動計畫要寫管線哪一階段的輸出會怎麼變（中間圖、中間量，不只最終判定），以及「出現什麼結果＝假說被否定」。改完先核中間結果，再看判定。判定變好、中間結果卻不符預期＝假說沒被證實，回覆要明寫「數字變好但機制未驗」，不得事後補故事。觸發案例：三個比例門檻在 5 張開發圖上把 51 條過殺全部排除，但那三個比例到底能不能區分細絲和結構，從來沒在中間層驗證過，20 張封存集一跑就破功。
- **diff 固定輸出四格**：修好的過殺／殘留的過殺／新增的過殺／新增的漏檢，候選級和工件級各一份。工件級的 NG 要逐張核對抓的是不是該抓的位置；「NG 圖仍判 NG」不得掩蓋抓錯位置或漏掉真缺陷。

**執行方式**：非預期翻轉、保護反例、四格＝機械；預期中間結果＝人簽核（LLM 附中間圖）。

## 紀律四：門檻附分佈，不附不算

**規則**

- 任何門檻重校或新增條件，都要附該特徵在**全體候選**（認同和過殺都算）上的分佈圖或分位表，門檻位置標在圖上。
- 認同群和過殺群在門檻兩側要有間隙。**兩群在門檻處重疊＝擬合，不是規則，退回。**
- **組內散布停止條件。** 對已成類的候選群，算這一類在每個判定量上的組內全距。組內全距大於這個量的判定可用窗口，就表示這個量對這一類沒有辨別力：**禁止用調整這個量來處理這一類，也不准換另一個量繼續找。** 實例：某一類的組內全距是判定窗口的 10 倍。
- 附靈敏度：門檻 ±20％ 時各翻轉幾張。翻轉數對微調很敏感＝門檻落在密集區，不可定版。
- **重拍擾動。** 定版前至少在一批不同日期取像的影像上重跑，翻轉數和 ±20％ 靈敏度並列。拿不到不同日期的影像，要明寫「成像擾動未驗」，不得省略。參數只對開發批那一天的光場成立＝擬合。觸發案例：取像條件換了三次，凍結常數和整套基線全部失效，詳見 [growth/06](../growth/06_imaging_domain_and_measurement_trust.md)。
- **數字出自生產實作。** 進定版文件的數字，一律出自跟機台同一份程式的掃描輸出；研究腳本只讀輸出畫圖，不碰影像解碼。這是為了避免兩套實作、兩種解碼造成常數不一致。

**執行方式**：機械。

## 紀律五：封存集只回總數

**規則**

- 資料分成兩條流：
  - **開發流**：可以挑失敗案例、看逐張細節、反覆迭代。
  - **稽核流（封存集）**：改法期間 LLM 不得讀逐張結果；改動凍結後才跑，只回報「翻轉幾張、候選數怎麼變」，不給逐張細節。
- 封存集在每輪**事前**用固定亂數種子抽樣並鎖住，排除所有曾經用過的影像；抽樣工具拒絕覆蓋既有清單。
- 看過逐張細節的封存集，自動降級成開發集，下一版要重抽。
- 「再多加一些覆核影像」一律先決定新圖進哪一條流。
- **真值與分母不變。** 改法期間不得改人工標籤、刪困難樣品、換評估分母、放寬驗收條件。標註有疑義就重新掛題問人；改判由使用者自己在覆核介面做，跨輪翻轉由總帳記錄。LLM 不得把標籤改成對演算法有利的答案。

**執行方式**：機械。判定檔和清單跨輪比對雜湊，矛盾列入總帳。

## 紀律六：複雜度記帳，並接受「不改」

**規則**

- 每輪的管線說明加報兩個數字：可調常數個數、判定分支數，和上一版比較。
- **常數變多、而只有開發集變好＝可疑，預設退回。**
- **計算形狀。** 管線說明裡每一步標三件事：**跑在什麼範圍**（全圖／ROI／只有候選）、**掃幾遍**、**核多大**。不必計時，寫說明時順手標。這是不用儀器的成本預測器：「在全圖上跑 20 圈 31×31 形態學」一寫出來，量級就看得到了。
- **改前預測成本方向。** 改動計畫要寫「這個改動多或少幾遍全圖掃描、範圍變大或變小，預期 CPU 核心秒增加、減少或不變」，改完用紀律七的數字對。用**工作量**講，不用「快慢」講，「我平行化了所以變快」這種話就混不進來。
- **提案格式。** 每輪最多提**兩個**有證據的假說，選一個先驗證。這是工作量限制，不是說演算法只能有兩種選擇。每個提案固定五要素：
  1. 目標誤檢群組、代表案例、目前確認的觀察。
  2. 原因假說、支持證據、還沒確認的部分。
  3. 和最接近的真瑕疵差在哪、保護反例。
  4. 最小實驗、預期中間結果、假說被否定的條件。
  5. 驗收條件、允許改動的範圍、怎麼回復。
- 以下都是**合法結論**，LLM 不得因為「沒改東西」而迴避：
  - 「本輪不改：不同意的案例無法一致解釋。」
  - 「表示法不足：門檻怎麼調都補不了，需要定義變更。」
  - 「資料不足：需要更多封存集才能判斷。」
  - 「**此題不能由數據回答**：需要＿＿（客戶允收標準、製程知識、光學條件、現場事實），我手上沒有，交還使用者。」LLM 會不自覺把問題縮到手上資料能回答的範圍，因為那是它唯一能自我驗證的地方。**不得用數據去逼近一個不在數據裡的答案。**

**執行方式**：提案五要素、每輪最多兩個假說、「數據答不了」的出口＝人簽核。

## 紀律七：效能預算

**為什麼這是硬約束**

在我們的產線上，下游動作（例如打印標記）是在掃描結束那一刻，取當下的判定快照。還沒算完的影像不在 NG 清單裡，就直接靜默漏標，不報錯、不留痕。影像佇列也有上限，取像比檢測快時會丟掉最舊的影像，同樣是靜默漏檢。**所以「算得慢」在產線上不會表現成節拍變長，而是表現成漏檢。**

**規則**

- **預算公式**：單張 CPU 預算（核心秒）＝邏輯核心數 ÷ 需求吞吐（張／秒）。預算綁機器，換機器要重算，不可沿用數字。
- **量 CPU 核心秒，不量 wall time。** 一張圖獨佔整台機器時，平行化會把 wall time 壓下去；但多台相機同時跑時，吃的是同一批核心，總計算量一點都沒少。觸發案例：一次效能重構讓單張 wall time 快了 4.7 倍，就被當成解決了；實測 CPU 核心秒零變化，多相機並行的吞吐仍然只有需求的幾分之一。再多開執行緒也不是解法：worker 從 6 開到 16，只拿回 1.1 倍。
- **每輪改動要報**：這條線的單張 CPU 核心秒，和上一版比較。
- **步驟級剖析是觸發式的，不是每輪例行。** 以下任一成立才做一次：這條線的核心秒比上一輪跳 30％ 以上（不論變快變慢）；超標倍數進入新的整數位（例如 1.x 變 2.x）；定版前必做一次。不每輪做，是因為表示法還沒定時，逐步驟數字擺在眼前會誘發過早優化，改一個還會變的步驟是白工。
- **超標的處置**：
  - 研究期不擋，可以繼續迭代，但檢核區塊要標「超出預算 n 倍」。
  - 不得在不知道自己超標多少的情況下前進，每輪都要報數。
  - **定版與接入前必須落在預算內**，或由使用者明示例外並記錄理由。超標時不得宣稱「可上線」「效能已解決」。
- **效能和判定是兩件事。** 為了省時間而放寬判定，屬於紀律二的定義變更或門檻重校，前置條件照舊，不因效能壓力豁免。

**執行方式**：機械（固定的效能量測工具）。

## 紀律八：方法族

**為什麼**

前面七條全在管「框架內怎麼改」，沒有一條問「框架對不對」。

觸發案例：最簡基準（全域門檻＋輪廓）在一張圖上失敗，原因是「背景沒有建模，固定門檻在不同底色下失效」。LLM 沒有修這個失敗，而是整個換成更強的方法族，之後六天八輪都在那個框架裡打補丁。每個補丁局部都說得通，也都通過了紀律三到六，因為那些紀律只看 diff，不看框架。最後是我一句物理判斷，讓它回到「建模背景再二值化」，也就是基準的同族修正，一天就收斂。那段期間 LLM 自己選了 6 次方法或規則，0 次留下；留下來的 2 次，都來自我的一句物理判斷。詳見 [growth/03](../growth/03_method_family_drift.md)。

使用者不寫演算法、也不必懂濾波器，但**能在基準失敗圖上判斷「該修還是該換」**。這條紀律把這個判斷從第十輪提前到第零天。

**規則**

- **8a 方法選擇書。** 每條線出第一個原型前，在現況卡固定一節「方法族」，列**至少三個方法族、由簡到繁**。每族寫三件事：假設影像長什麼樣（這方法在什麼前提下成立）、會在哪裡失敗（前提不成立時的症狀）、計算形狀。**最簡的那族必須實跑**，失敗處出圖組成**方法包**：只放中間圖和失敗圖，不放判定結果和過殺率。使用者在基準失敗圖上回答「修同族」或「換族」，LLM 不得代答。
- **8b 換族聲明。** 換方法族的那一輪，README 固定一節「本輪為何不是修上一版，而是換方法」，必含三項：**同族最小修正**是什麼、**為何它不可能成立**、**證據**在哪。三項寫不齊就不得換族。沒換族的輪次，這一節寫「本輪未換方法族」。
- **8c 方法層記分板。** 現況卡「方法族」節固定一張表：日期｜方法族｜誰提的（LLM／使用者）｜理由｜下場。每次換族、撤回、定版都加一列，**不改寫舊列**。它不會讓 LLM 變聰明，但能讓使用者在第三輪就看出「LLM 提的框架又要死了」，而不是等到第十輪。
- **基準失敗，先修同族。** 基準在某些圖上失敗時，下一步預設是針對診斷出的原因做同族最小修正，不是換更強的工具。
- **每輪例行一句**：「本輪失敗類型的最簡處理方法是什麼、用了沒有、沒用的理由。」這句話很便宜，卻製造出一個使用者可以反問的具體主張。

**執行方式**：8a＝人簽核；8b＝機械（檢查三項是否齊全）＋人簽核；8c＝人工維護，定版時核對列數不少於換族次數。

範本見 [templates/method_selection.md](../templates/method_selection.md)、[templates/scoreboards.md](../templates/scoreboards.md)。

## 紀律九：產包前看圖初判

這條是我立的。

**為什麼**

覆核包的組成大多是數值，只有標記圖是圖。LLM 產包時習慣只讀 CSV 和 JSON 排表格，候選長什麼樣，要等使用者在介面上看了才知道。觸發案例：一包 253 條候選就是這樣交出去的，我看完說「演算法感覺被改爛了」。LLM 事後抽 30 條看圖，才知道 9 條是真瑕疵、18 條是產品結構的殘影、3 條不確定；被新版拿掉的 14 條裡，還有 3 條看起來是真的。這些在產包前看 11 張裁圖表（約 6 萬 tokens）就能知道。

使用者的時間是最稀缺的資源。LLM 的眼睛要用在使用者前面，而且要留下可以對答案的紀錄。詳見 [growth/05](../growth/05_human_in_the_loop.md)。

**規則**

- **先看再出。** 任何覆核包交付前，LLM 都要用影像工具**看過每一條要進包的候選**，逐條寫初判；只讀數值產包＝退回。唯一例外是封存集（紀律五，永遠不看）。一千條以內全看、不抽樣；每條約 250 tokens，不佔紀律一的看圖預算。
- **看什麼**：每條候選裁成三格（原圖／原圖＋候選輪廓／原圖＋結構圖層），放大 2 倍以上，排成裁圖表。LLM 逐張看，不看縮圖，不只看數值欄。
- **寫什麼**：初判檔每條候選一列，包括 `prejudge`（真／結構殘影／不確定）、`family`（是結構殘影就填來源，用本線固定詞彙；是真的就填形態）、`reason`（一句白話，同紀律一，不得含量名）、`sheet`（看的是哪張裁圖表）。覆核包 README 固定一節，只放計數。
- **初判的三個用途**：
  1. **產包決策。** 初判為結構殘影、而且同一來源至少 2 例，就是紀律一所說的「類別」，產包前先提同族結構修正案。使用者說本輪不修，才連同進包，README 標明家族和條數。**LLM 不得手工把候選從包裡拿掉**，包就是演算法現行的輸出，拿掉等於把過殺藏起來。
  2. **不進覆核介面。** 介面不顯示初判，候選備註也不得寫初判字樣，避免錨定人的判斷。
  3. **可信度記帳。** 使用者判完後，用腳本算「初判 vs 人工」對照表，寫進診斷表，並累計到現況卡的「LLM 看圖記分板」。命中率低，要修的是 LLM 看圖的方法和家族詞彙，不是演算法。
- **測試批也要初判**，但初判只能寫進初判檔，不得據以改任何程式、門檻或規則。

**執行方式**：機械（初判檔對候選清單逐條齊全、值域正確、理由不含量名、裁圖表存在、README 計數相符、介面備註不含初判字樣）＋人簽核（使用者判完後看對照表）。
