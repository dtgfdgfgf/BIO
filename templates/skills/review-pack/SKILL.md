# 覆核包：產出與回讀

> 迭代紀律正本＝`docs/iteration_discipline.md`（紀律零到九）；本 skill 只寫產包與回讀的程序，不複製條文。
> 覆核介面的資料契約正本＝`tools/reviewui/README.md`；下方 §契約 是最小欄位摘要。

## 鐵律（違反任一項＝整包無效）

1. **不能只丟包。** 同時完整說明管線每一步的操作、參數與門檻值、NG 和 OK 怎麼區分。
2. **要問什麼由人定。** 產包前先交一頁「本輪想問什麼、為什麼、預期關掉哪個開放問題」，不含任何數值分析；使用者點頭才產包。LLM 自己決定議題時，只會問它算得出來的東西。
3. **先過階段閘門。** 紀律零的開工前四問任一答「否」，只能出定義包、結構包或方法包，不得出判別包。
4. **產包前逐條看圖初判（紀律九）。** 每一條要進包的候選都要看過裁圖並寫進 `llm_prejudge.csv`；只讀數值產包＝退回。
5. **包＝演算法現行輸出。** LLM 不得手工把候選從包裡拿掉，拿掉等於把過殺藏起來。
6. **README 裡每個數字都要能從包內檔案重算**，交付前跑檢查。

## 包的四種型別（先定型再組包）

| 型別 | 問什麼 | 前提 | 不准放什麼 |
|---|---|---|---|
| 定義包 | 「這算不算瑕疵？這是什麼？」幾張典型放大圖＋一句話問題 | 無 | 任何量名、門檻、統計表、過殺漏檢率 |
| 結構包 | 「分層、ROI、建模對不對？」 | 定義已拍板 | 判定結果、過殺漏檢率 |
| 方法包 | 「最簡基準在這些圖上這樣失敗，該修同族還是換族？」方法選擇書＋逐階段中間圖與失敗圖（5～10 張） | 第一個原型前、每次換方法族前 | 判定結果、過殺漏檢率、門檻數值表；不得代使用者回答 |
| 判別包 | 門檻、灰區、分層；下方完整組成 | 定義與結構都已結案、方法族已簽核 | — |

候選檔的 `purpose` 開頭標型別：`[定義]`／`[結構]`／`[方法]`／`[判別]`。定義包裡出現數值表＝格式錯誤，退回。

出定義題之前，先數這類東西在整批出現幾張，寫進題目（例如「這類在 29 張裡有 20 張」），並附一排由大到小的實例，讓使用者指出分界在哪。放大裁圖會讓每個小東西都像瑕疵，不給普遍度，人會答「全部要抓」。

## 組成（判別包全部要；其他型別至少要 ⑤⑥⑦）

1. **管線說明**：每步操作、參數、門檻；NG／OK 區分寫成可執行的式子；與上一版的差異，每項標改動類型並附常數數與分支數前後比較。
2. **全量掃描數值**：出自生產實作的掃描輸出，不抽樣；兩層輸出（每張摘要＋每個候選明細）。
3. **分佈與分層**：分層張數、與上一版差異逐張歸因；候選清單落地成檔案。
4. **灰區清單**：本輪灰區的定義與張數。
5. **標記圖與候選檔**：原圖尺寸出圖；附 `candidates.json`（見 §契約）。現行已保留的候選也要用灰色細線畫出來、標「已保留、唯讀」，否則使用者會把已抓到的重畫成漏檢。
6. **目錄與一鍵開啟**：`output/review/round_<YYYYMMDD>_<標籤>_v<n>/`，平放、依名稱排序＝依日期；包內附一鍵開啟覆核介面的捷徑。舊包不搬、不刪、不改寫。
7. **LLM 初判**：`llm_prejudge.csv`＋README 固定一節「LLM 初判」只放計數。

## 產包前看圖初判（紀律九）

1. 寫好 `candidates.json`。
2. 用工具把每條候選裁成三格（原圖／原圖＋候選輪廓／原圖＋結構圖層），放大 2 倍以上排成裁圖表，同時產出 `llm_prejudge.csv` 骨架。
3. LLM **逐張看裁圖表**，填 `prejudge`（真／結構殘影／不確定）、`family`、`reason`（一句白話，不含量名）、`sheet`。
4. 結構殘影同源 2 例以上＝先提同族結構修正案，使用者說本輪不修才連同進包。
5. 跑初判檢查，PASS 才交付。

初判**不進覆核介面**，候選的 `note` 也不得寫初判字樣，避免錨定人的判斷。封存集永遠不看。

## 契約（最小欄位；簡化示意，不是原工具的完整契約）

`candidates.json`：

```json
{
  "schema": "review.candidates.v1",
  "purpose": "[判別] 本輪為了什麼，一句話",
  "supersedes": "round_<YYYYMMDD>_<標籤>_v1（第一輪填 null）",
  "classes": ["細絲"],
  "reason_classes": ["正常結構邊緣", "表面紋理", "反光", "其他"],
  "images": [
    {
      "id": "img001",
      "file": "images/img001.jpg",
      "sha256": "<原圖雜湊>",
      "meta": {"batch": "A", "slot": 12},
      "candidates": [
        {
          "id": "T1",
          "class": "細絲",
          "kept": true,
          "polygon": [[120, 40], [180, 42], [181, 60], [121, 58]],
          "note": ""
        }
      ]
    }
  ]
}
```

- 座標一律是**原圖像素座標**；幾何用 `polygon`、`polyline`（細長物）或 `bbox` 之一。
- `kept` 每條必填：現行判定是否保留這個候選。缺了，跨輪總帳的「抓到沒」就只能記「未知」。
- `reason_classes`：非認同候選「它其實是什麼」的固定詞彙，依本線可能的假訊號來源列。使用者可以在介面上當場新增類別。

人工判定（覆核介面寫出的 `human_review/review.json`）：

```json
{
  "schema": "review.result.v1",
  "images": {
    "img001": {
      "reviewed": true,
      "verdict": {"細絲": "有"},
      "defects": {
        "T1": {"label": "false_positive", "reason": "正常結構邊緣", "note": "<使用者原文>"}
      },
      "manual_marks": [
        {"id": "M1", "class": "細絲", "polygon": [[300, 80], [340, 82], [341, 95], [301, 93]]}
      ]
    }
  },
  "answers": {"Q1": {"kind": "single", "value": "A"}}
}
```

## 回讀人工判定

- **`reviewed=false`（或圖不在 `images` 裡）＝整張未覆核，其候選一律不計、不得當成認同。** `reviewed=true` 且 `defects` 沒列到的候選，才是認同。
- `note` 原文引用，不改寫。
- `manual_marks` 是人畫的漏檢，只用來比對和報告，不自動回寫標籤。前一輪畫過的漏檢，使用者不會重畫；本輪沒有新畫不等於沒有漏檢，漏檢總數以跨輪總帳為準。
- 使用者在介面上答了題，答案就已經寫進檔案；引用待答題之前，先讀答案，不要看有沒有定稿檔。
- **回讀第一步＝先看圖，再填診斷表（紀律一）**，此時不改碼。選圖順序：
  1. 每個原因類別 1～2 張典型圖（長期複用的錨點圖）。
  2. 本輪必看：現行保留的候選、人判過殺但仍保留的、本輪新畫的漏檢、第一次出現的原因類別。
  3. 使用者打星號要 LLM 一定看的。
  4. LLM 主動要求的：先寫「我要看 X，因為要回答 Y」，使用者批准才看。
- 跑初判對照：「初判 vs 人工」寫進診斷表，並在現況卡的 LLM 看圖記分板加一列。
- 人工指認過的候選累積成範例集，**範例集就是回歸測試**：任何新版本，範例集翻轉要為零，或每條翻轉都在預寫的翻轉清單裡。

## 要問使用者的事，掛在圖上問

- 診斷中要問使用者的事，寫成 `questions.json` 掛回覆核介面，對話裡只給摘要。
- 每題都要錨到能看的東西：本輪候選、人工標記、其他輪的候選，或 LLM 自己框的區域；附裁圖。沒有錨點也沒有附圖的問題，不得掛。
- 回答格式寫清楚：單選、多選、逐處回答、文字。選項要能單選，並附後果數字（過殺或漏檢張數怎麼變）。
- 契約不夠用時，先升級契約，不退回對話裡問。
- 結案只有兩種：之後某一輪重掛並答完，或使用者明說不答、已過時，在題目上記下日期和原話。不刪題，不改答案。

## 不做什麼

- 覆核包只服務拍板，不等於定版。
- 載入本 skill 不等於授權改演算法；改動照迭代紀律走。
