# 每輪「紀律檢核」區塊與配套表格

> **Summary (EN)**: The checklist block that every algorithm-change reply must carry (one row per rule, ten rows; a missing row means the change may not enter a review pack or be frozen), plus the forms that feed it: the stage-gate questions, the diagnosis table, the proposal format, the change plan with a pre-written flip list, the prejudge file, and the specification of the mechanical checks so you can write your own scripts.

規則全文見 [discipline/rules.md](../discipline/rules.md)。

## 1. 紀律檢核區塊

每次改演算法的回覆都要附。**缺任一列＝這次改動不完整，不得進覆核包或定版。**

```text
紀律檢核（iteration discipline v7）
零 開工四問：定義拍板＝是／否；成像穩定＝是／否；未標出的結構層＝…；本輪關掉＝Q…；最簡基準＝已跑／未跑／不適用（方法選擇書＝…）；使用者簽核＝是／否；重型分析＝未啟動／已啟動（閘門通過後）
一 診斷表：路徑＝…；已看圖＝n／m 張（t tokens）；類別數＝n；單例列「無法一致解釋」＝m 例；翻轉集＝k 條（≤1 退回）；受益／影響張數＝a／b
二 改動類型：bug／定義變更／門檻重校／新增條件／換方法路線（新增條件已核准＝是／否；換路線聲明＝路徑）
三 改動計畫：預期翻轉＝…；實際翻轉＝…；非預期翻轉＝0／k（k>0 已退回）；保護反例＝id…（翻轉＝0／k）；預期中間結果＝…（符合／不符）；否定條件＝…；四格（候選級／工件級）＝修好的過殺 a／殘留過殺 b／新增過殺 c／新增漏檢 d
四 分佈：圖或表＝…；門檻處兩群間隙＝有／無；±20％ 翻轉＝a／b 張；重拍擾動＝已驗（批次＝…，翻轉 n 張）／未驗
五 封存集：本輪＝有／無；只回總數＝翻轉 x 張；逐張細節未讀＝是；標籤／樣品／分母未變＝是
六 複雜度：常數 n→n′；分支 m→m′；計算形狀已標＝是／否；成本方向預測＝增／減／不變；假說數＝1／2（五要素齊＝是）；合法結論＝無／本輪不改／表示法不足／資料不足／此題不能由數據回答
七 效能：本線 CPU 核心秒 c→c′；預算 b；在預算內／超出 n 倍；步驟剖析＝未觸發／已附
八 方法路線：方法選擇書＝路徑／未寫；本輪換路線＝無／有（聲明＝路徑）；本輪失敗類型的最簡處理＝…，用了／沒用，理由＝…；記分板已更新＝是／否
九 看圖初判：初判檔＝路徑；看過＝n／n 條（裁圖表 k 張，約 t tokens）；初判＝真 a／結構殘影 b／不確定 c；同源 ≥2 例的家族＝…（本輪先修／使用者指示不修）；檢查＝PASS／FAIL；前輪初判 vs 人工＝真命中 x／y、結構殘影命中 u／v
```

## 3. 診斷表（紀律一）

讀完覆核結果後的第一個產物。此時不改碼。

| 候選 id | 影像 | 我看到什麼 | 人工判定＋備註原文 | 失敗階段 | 物理原因 | 類別 |
|---|---|---|---|---|---|---|
| T4 | img07 | 沿著產品邊緣的一條亮線，兩端接到轉角，寬度跟邊緣一致 | 過殺：「這是邊」 | 判定 | 結構邊緣沒標出來 | 結構邊緣 |
| T9 | img12 | 一段深色、粗細均勻的細絲，跨過兩種底色 | 漏檢（人工畫出） | 產生 | 固定門檻在淺底色上切斷 | 跨底色細絲 |

- 「我看到什麼」寫顏色、形態、連續性、和周圍結構的關係，**不得出現量名**。
- 「失敗階段」只填「產生」或「判定」。填「產生」的，本輪只能走定義變更或表示法路線。
- 同類 2 例以上、能用同一句物理解釋，才准提修改案；單例列在表下的「無法一致解釋」清單。

## 4. 提案（紀律六；每輪最多兩個，選一個先驗證）

```markdown
### 提案 A：<一句話>

1. 目標誤檢群組：<類別名>，代表案例 <id…>；目前確認的觀察：<…>
2. 原因假說：<…>；支持證據：<…>；還沒確認的部分：<…>
3. 和最接近的真瑕疵差在哪：<…>；保護反例：<id，必須出自人工指認過的範例集>
4. 最小實驗：<…>；預期中間結果：<哪一階段的輸出會怎麼變>；否定條件：<出現什麼＝假說被否定>
5. 驗收條件：<…>；允許改動的範圍：<…>；回復方式：<…>

改動類型：<bug／定義變更／門檻重校／新增條件／換方法路線>
受益張數：<a>　影響張數：<b>（受益 ≤1 張＝列已知限制，不提案）
計算形狀變化：<多／少幾遍全圖掃描、範圍變大／變小>；預期 CPU 核心秒：<增／減／不變>
```

## 5. 改動計畫與翻轉清單（紀律三）

改動前寫好、存成檔案，改完拿 diff 對：

```json
{
  "change": "一句話描述改動",
  "type": "門檻重校",
  "expected_flip": ["img03:T4", "img07:T2"],
  "expected_no_flip": ["img11:T1"],
  "protect": ["img05:T3"],
  "expected_intermediate": "結構圖層在 img03、img07 的邊緣處要變寬，其他圖不變",
  "falsified_if": "img03:T4 翻轉了，但結構圖層沒有變化",
  "holdout_expected_flips": 2
}
```

改完的 diff 固定輸出四格，候選級和工件級各一份：

|---|---|---|
| 修好的過殺 | | |
| 殘留的過殺 | | |
| 新增的過殺 | | |
| 新增的漏檢 | | |

## 7. 機械檢查規格（想自己寫腳本時）

原專案把下面這些都寫成了腳本，但腳本綁內部資料格式，沒有放出來。這裡列規格，讓你可以用自己的格式實作。

| 檢查 | 輸入 | FAIL 條件 |
|---|---|---|
| 診斷表 | 診斷表 markdown | 「我看到什麼」欄空白、含量名清單裡的詞、表格 0 列 |
| 翻轉集 | 翻轉清單 | 提案的翻轉集 ≤1 條 |
| 保護反例 | 翻轉清單＋新舊輸出 | 標為保護的候選翻轉了 |
| 四格 | 新舊輸出＋人工判定 | 無法產出四格（缺人工判定欄） |
| 看圖預算 | 本輪看過的圖清單 | 估算 tokens 超過上限 |
| 範例集回歸 | 人工指認過的候選＋本輪輸出 | 任一條翻轉，且不在預寫翻轉清單裡 |
| 換路線聲明 | 輪次 README | 缺「原路線的最小修正」「為何不可能成立」「證據」任一項 |
| 覆核包數字 | 覆核包 README＋包內檔案 | README 表格裡的數字和包內檔案重算的不一致 |
| 初判完整 | 初判檔＋候選檔 | 有候選沒初判、值域不對、理由含量名、裁圖表不存在、README 計數不符 |
| 初判不進介面 | 候選檔 | 候選 `note` 含「初判」「結構殘影」「LLM」字樣 |
| 真值不變 | 人工判定檔＋清單的跨輪雜湊 | 改法期間雜湊改變且總帳沒有對應的人工改判紀錄 |
| 開放問題壽命 | 跨輪總帳 | 同一題掛滿 2 輪沒答（觸發後該線停止出新包） |
